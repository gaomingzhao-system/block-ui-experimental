Fits right into Vue’s v-html.

Each download is one HTML fragment, including its own style element. Put the complete fragment in your existing trusted string and render it into a flow-content container:

<div v-html="content"></div>

The supplied fragments contain no literal backticks, interpolation markers, or backslashes, so they can be pasted into a backtick-delimited string without escaping. They contain no Vue directives and need no Vue compilation.

Keep the embedded style as the first child of the block. Use a host such as <div>, not <p>. Vue does not sanitize v-html; only render content you trust. HTML filtering in some editors can remove style elements.

Read Vue’s v-html documentation ↗

Your words. Your colors.

Edit the text, links, and heading levels to fit your page. Replace the example destinations and fictional people before publishing. The theme control above demonstrates shared CSS custom properties; every fragment also has its own light-theme defaults.

<div style="--bui-primary: #146c51; --bui-tint: #eaf6ef;">
  <!-- Paste your complete block here. -->
</div>

Available properties: --bui-surface, --bui-text, --bui-muted, --bui-primary, --bui-primary-text, --bui-tint, and --bui-border. Check contrast whenever you change a color pair.

Scopes keep a block’s selectors local; they are not Shadow DOM. Your page’s CSS can still affect a block, especially high-specificity or !important rules. Check the result in your actual page layout.

An honest note about copying.

HTML and CSS cannot write to your clipboard. Get HTML opens the complete, selectable source; copying uses your browser’s native copy command. Downloads save the same fragment with its embedded styles, without a network request.

A one-click clipboard button would need JavaScript and the Clipboard API. This library and documentation site intentionally stay script-free. About the Clipboard API ↗

Modern CSS, native HTML.

The blocks use an embedded, implicit @scope to keep their styles together. Use a current browser with CSS @scope support. Older browsers retain the semantic content and native FAQ interaction, but may show unstyled blocks.

  • Fluid spacing, logical properties, and wrapping layouts adapt to the available space. Tables and carousels scroll inside their own labeled region when necessary.
  • FAQ and form controls use native HTML interaction. The carousel uses native scrolling and CSS scroll snap. Blocks can be repeated without ID collisions, and there is no animation, JavaScript, CDN, font download, or analytics.
  • The documentation theme switch uses :has() and lasts for the current page view. Downloads keep their portable light defaults; copy your preferred color properties too if you want a custom theme.
  • Your Content Security Policy must allow the embedded styles, for example through matching style hashes or server-provided nonces. A policy that blocks inline styles will block these component styles.
